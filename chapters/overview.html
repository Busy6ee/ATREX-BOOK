Chapter 01

전체 구조 한눈에

ARTEX 는 LLM 이 조종하는 여러 에이전트가 스스로 목표를 쪼개고, 도구를 실행하고, 결과를 그래프에 쌓으며 장시간 작업을 이끄는 시스템입니다. 이 장은 그 시스템을 코드 규모와 패키지 지도로 먼저 조망하고, 이후 장에서 어디를 어떤 순서로 파고들지 정합니다.

  • ARTEX 가 풀려는 세 가지 구조적 문제를 설명한다
  • Go 백엔드의 패키지를 역할 단위로 분류하고 코드 규모를 비교한다
  • 요청 하나가 프런트엔드에서 DB 와 에이전트까지 흐르는 계층을 그릴 수 있다

이 책의 범위

해설서의 선

ARTEX 는 허가받은 환경에서 침투 테스트를 자동화하는 도구입니다. 이 책은 그 도구를 자율 에이전트 시스템의 설계 사례로 읽습니다. 다루는 것은 아키텍처, 에이전트 구성, 상태 관리, 안전장치, 방어 관점입니다. 에이전트의 프롬프트 원문, 공격 절차, 페이로드는 싣지 않습니다. 허가 없는 대상에 대한 사용은 불법이며, 저장소 자체도 방어와 학습 목적으로 공개되어 있습니다.

ARTEX 가 풀려는 세 가지 구조적 문제

장시간 자율 작업에는 "모델 한 번 호출"로는 풀리지 않는 문제가 있습니다. ARTEX 의 설계는 이 셋에 대한 답으로 읽으면 가장 잘 이해됩니다.

패키지 지도와 코드 규모

Go 백엔드는 약 6.4만 줄(테스트 제외)이며 서버와 DB 계층이 약 71%를 차지합니다. 에이전트 로직은 7천 줄대로 의외로 작습니다. 복잡도의 대부분은 "에이전트를 똑똑하게 만드는 코드"가 아니라 "에이전트를 오래, 안전하게, 관측 가능하게 돌리는 코드"에 있습니다.

주석과 구현의 불일치 읽기

cmd/artex/main.go 의 패키지 주석은 아직 "dual SQLite graph stores"라고 적혀 있습니다. 상류에서 SQLite 로 시작해 PostgreSQL 로 옮겨 간 흔적입니다. 코드 읽기에서는 주석보다 go.mod 의 의존성과 db/schema.sql 이 신뢰할 근거입니다. 이 책의 서술은 후자에 맞춥니다.

기동 순서

main.go 의 run() 은 160줄이 채 안 되지만, 순서에 이유가 있습니다.

  1. 로그 캡처 시작: 기동 로그까지 메모리 싱크에 담아 /logs 화면에서 보이게 한다.
  2. 자가 업데이트 부트스트랩: 새 바이너리로 교체 중이거나 롤백해야 하면 저장소를 열기도 전에 종료 코드 75 로 나간다. 비싼 일을 하기 전에 끝내는 순서다.
  3. 종료 컨텍스트 생성: 시그널 컨텍스트의 자식이 아니라 WithCancelCause 로 따로 만든다. 부모의 단순 Canceled 가 먼저 도착해 종료 원인을 잃는 경쟁을 피하려는 설계다.
  4. Manager 생성: 데이터 디렉터리, 프록시 주소로 저장소와 엔진을 연다.
  5. 정착 타이머: 새 빌드가 30초 살아남으면 업그레이드 표식을 지운다. 그 전에 죽으면 시도 횟수가 쌓여 롤백된다.
  6. HTTP 서버 기동 후 시그널 또는 재시작 요청을 기다리고, 종료 코드를 정한다(0: 정상 정지, 75: 재기동 요청).

핵심 정리

  1. ARTEX 의 설계는 연속성, 병렬성, 통제라는 세 구조적 문제에 대한 답으로 읽을 수 있다.
  2. 코드의 약 71%가 server 와 db 다. 에이전트 두뇌보다 운영·관측·복원력 코드가 훨씬 크다.
  3. 상태는 세션이 아니라 PostgreSQL 이 쥔다. 에이전트 세션은 언제든 버려도 되는 일회용이다.
  4. 모든 부작용은 도구를 통해서만 일어나고, 도구는 훅 게이트를 지난다.
  5. 이 책은 방어와 학습 목적의 해설서이며 공격 절차와 프롬프트 원문은 다루지 않는다.

확인 퀴즈

코드 규모에서 가장 큰 비중을 차지하는 패키지 조합은?

server 25.7k, db 19.5k 줄로 전체 약 6.4만 줄의 약 71%입니다. 에이전트 로직(agent)은 약 7.5k 줄입니다.

planner 가 매번 새 세션으로 깨어나는데도 작업이 이어지는 근거로 가장 알맞은 것은?

세션은 일회용이고, 연속성은 저장소(그래프, todolist)에 있습니다. 2장과 5장에서 다룹니다.

종료 컨텍스트를 시그널 컨텍스트의 자식으로 만들지 않은 이유는?

main.go 의 shutdownContext 주석이 이 경쟁을 명시합니다.

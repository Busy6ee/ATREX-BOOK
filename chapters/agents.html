Chapter 03

에이전트 역할 구성

ARTEX 는 하나의 만능 에이전트 대신 목표 분해, 계획, 실행, 사람 인터페이스로 역할을 쪼갭니다. 쪼갠 이유는 성능보다 통제에 가깝습니다. 역할마다 읽고 쓸 수 있는 도구가 달라서, 한 에이전트가 잘못 판단해도 피해가 그 역할의 권한 안에 머뭅니다.

  • 네 가지 핵심 역할의 입력, 출력, 수명, 책임을 구분한다
  • 역할별 도구 세트를 읽기, 기록, 흐름 제어, 범위 설정으로 분류해 최소 권한 설계를 평가한다
  • 한 의도가 역할 사이를 지나가는 순서를 그릴 수 있다

역할 지도

코드 위치는 agent/ 패키지입니다. 오케스트레이션(어떤 역할을 언제 깨우는가)은 서버의 엔진이 맡고(장), 이 장은 역할 자체의 설계를 봅니다.

한 의도가 지나가는 길

역할이 분리되어 있으므로 하나의 탐색 방향은 여러 역할을 거쳐 갑니다. 아래 시뮬레이터는 그 순서를 단계별로 보여 줍니다. 가운데 세로선이 각 역할이고, 오른쪽 끝이 공유 저장소(PostgreSQL 의 두 그래프)입니다. 역할끼리 직접 대화하지 않고 저장소를 통해서만 간접적으로 만난다는 점을 확인하세요.

이 행렬에서 읽을 수 있는 설계 판단
  • 실행자(worker)는 계획을 만들지 못한다. 의도 추가, 목표 판정, 실행 중단 도구가 없다. 한 의도만 맡고 결과를 쓰고 끝난다.
  • 계획자(planner)는 사실을 쓰지 못한다. 사실 기록과 자산 등록 도구가 없다. 결과는 실행자만 만든다. 계획자는 읽고 방향을 정한다.
  • 범위와 제약을 바꾸는 권한은 가장 좁다. 목표 분해기와 사람 인터페이스, 그리고 계획자의 범위 도구에 한정되고 실행자에게는 없다. 실행자가 스스로 허용 범위를 넓힐 수 없다.
  • 한 번에 전체 작업을 끝내 버리는 도구는 기본으로 막아 둔다. 목표 달성 일괄 선언 도구(goal_met)는 목록에는 있지만 어느 역할에도 기본 연결하지 않았다. 개별 목표를 증명해 가는 경로와 겹치고 오판 비용이 크기 때문이다.

역할을 나눈 이유

분리얻는 것치르는 것
계획과 실행의 분리실행 에이전트의 컨텍스트가 한 의도로 좁아져 길어도 목적을 잃지 않는다. 계획자는 짧은 세션을 자주 돌려 비용을 통제한다둘 사이의 정보가 저장소를 거치므로 기록이 부실하면 계획이 흔들린다
사람 개입 경로를 별도 역할로사람의 지시가 자율 흐름의 규칙(의도 선점, 상태 전이)을 우회하지 않고 같은 저장소 규칙을 따른다사람이 넣은 의도도 같은 큐에서 경쟁한다
목표 분해를 한 번만목표와 제약이 작업 시작 시점에 고정되어 이후 에이전트가 경계를 흔들 수 없다중간에 바꾸려면 사람이 명시적으로 수정해야 한다
역할 분리가 보안 경계는 아니다

도구 권한 분리는 "모델이 실수했을 때 피해의 범위"를 줄일 뿐, 악의적 입력에 대한 방어선이 아닙니다. 실행자는 공통 기본 도구(셸 포함)를 갖고 있어, 실제 부작용의 통제는 모든 도구 호출이 지나는 게이트와 사람 승인(장)이 담당합니다. 역할 권한은 첫 번째 층, 게이트는 두 번째 층으로 읽어야 합니다.

에이전트마다 주입되는 설정

각 역할 객체는 생성 후 여러 설정 함수로 조정됩니다. 값을 상수로 박지 않고 함수로 주입하는 것이 특징입니다. 호출 시점마다 최신 설정을 읽으므로 UI 에서 바꾼 값이 재시작 없이 다음 실행부터 반영됩니다.

동시에 도는 실행자 수의 기본값은 3이고 시스템 설정에서 바꿉니다. "중단·지시 콜백이 없으면 도구도 없다"는 규칙은 기능 존재 여부를 와이어링 단계에서 결정한다는 뜻이며, 테스트 환경에서 부작용 있는 도구가 실수로 노출되지 않게 하는 안전 장치이기도 합니다.

핵심 정리

  1. 목표 분해, 계획, 실행, 사람 인터페이스의 네 역할이 저장소를 통해서만 간접적으로 만난다.
  2. planner 는 읽고 방향을 정하고, worker 는 한 의도를 수행해 기록한다. 서로의 도구를 갖지 않는다.
  3. 범위와 제약을 바꾸는 권한은 가장 좁게, 전체 작업 종료 선언 도구는 기본 비활성으로 둔다.
  4. 역할 권한은 피해 범위를 줄이는 첫 번째 층이고, 보안 경계는 도구 호출 게이트가 맡는다.
  5. 설정은 함수로 주입되어 재시작 없이 다음 실행부터 반영된다.

확인 퀴즈

planner 에게 사실 기록 도구를 주지 않은 설계의 의도로 가장 알맞은 것은?

계획자는 읽기와 흐름 제어, 실행자는 읽기와 기록으로 나뉩니다. 한쪽이 양쪽을 다 갖는 만능 에이전트가 되지 않게 합니다.

목표 달성 일괄 선언 도구(goal_met)가 기본으로 어느 역할에도 연결되지 않은 이유는?

목록에는 있어 운영자가 필요하면 명시적으로 연결할 수 있습니다. 위험한 도구를 없애는 대신 기본값을 닫아 두는 설계입니다.

역할별 도구 권한 분리를 보안 경계로 보면 안 되는 이유는?

역할 권한은 실수의 피해 범위를 줄이는 첫 번째 층입니다. 두 번째 층이 장의 게이트입니다.
